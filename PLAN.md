# Dota Drafter: план

Статус: план одобрен 16.10.2026. **Все этапы 0–7 готовы.** Осталось только то, что требует игры: замер точности чтения экрана на твоих скриншотах, проверка блока `draft` в GSI и замер FPS с оверлеем.
Патч на момент плана: 7.41f.

Решения по вопросам: аккаунт `1477734386` (Ancient 1, данные матчей открыты). Ранг берём из профиля OpenDota. Только рейтинговый All Pick. Только Windows 11. Rust установлен. Старый конфиг GSI на этапе 5 удаляем и ставим свой. Скриншоты драфта пользователь пришлёт перед этапом 6: **напомнить**. Коммит после каждого этапа. Факты и замеры, на которых основан план, лежат в [RESEARCH.md](RESEARCH.md).

## Коротко о главном

- **Матчи берём из OpenDota Explorer.** За сутки там около 476 тыс. ранговых матчей с героями, один запрос отдаёт 50 тыс. за секунду. Сбор данных займёт минуты, а не дни.
- **Позиции, билды и порядок прокачки — только из Stratz.** У OpenDota этих данных по пабам нет: разобранных ранговых матчей за неделю ноль. Нужен бесплатный токен Stratz (вопрос 3).
- **Почему прошлое чтение экрана работало плохо, и что меняем.** Скорее всего, сравнивались картинки с сайта с картинкой всего монитора. Теперь захватываем **только окно Доты** через Windows Graphics Capture, поэтому оверлей не попадает в кадр. Зоны фиксируются калибровкой. Сравнение идёт с портретами, вырезанными из **твоей же игры**: приложение учится на твоих исправлениях. Если уверенности нет, слот остаётся пустым. Точность меряем на сохранённых скриншотах до того, как функцию включать.
- **Valve в 2024 закрыла данные об игроках на стадии драфта.** Мы такие данные и не используем: только общая статистика по героям (как у Dota Plus) и то, что видно на экране.

## Архитектура

```

│ main window: React + TS, Liquid Glass   │  HTTP  │ FastAPI на 127.0.0.1:<случайный порт>    │
│ overlay window: прозрачное, поверх всех,│◄──────►│  + токен в заголовке                     │
│   Acrylic, сквозные клики               │   WS   │ data/   сбор OpenDota, Stratz, Valve     │
│ global-shortcut, window-state,          │        │ model/  модель, подсказки, объяснения    │
│ single-instance, запуск sidecar         │        │ builds/ теги героев, правила, билды      │
└─────────────────────────────────────────┘        │ gsi/    приём GSI (свой порт)            │
                                                   │ vision/ захват окна, шаблоны OpenCV      │
        Dota 2 ── GSI POST ──────────────────────► │ storage: DuckDB + Parquet, кэш иконок    │
                                                   └──────────────────────────────────────────┘
```

Структура репозитория:

```
backend/   requirements.txt (версии зафиксированы), drafter/{data,model,builds,gsi,vision,api}, cli.py, tests/
app/       Tauri 2 + React + TS (Vite), src-tauri/
shared/    hero_names.json, item_names.json (из dota2-tierlist), hero_tags.yaml, build_rules.yaml
data/      (в .gitignore) parquet матчей, кэш Stratz, модели, иконки, шаблоны портретов
reports/   отчёты модели и точности чтения экрана
```

Почему Tauri, а не Electron: прозрачное окно поверх всех, Acrylic, сквозные клики, глобальные клавиши и сохранение позиции у Tauri 2 есть из коробки или плагинами. Сам Tauri весит около 10 МБ, Electron около 150 МБ. WebView2 построен на Chromium, поэтому преломление через SVG-фильтр из твоего тир-листа заработает. Electron понадобится, только если на этапе 4 сквозные клики или Acrylic поведут себя плохо поверх Доты. Тогда скажу и предложу замену.

## Этапы

Каждый этап заканчивается коротким отчётом «что сделано и как проверить», а этот файл обновляется.

### Этап 0. Подготовка
- Установить Rust (`winget install Rustlang.Rustup`, нужно твоё согласие, вопрос 4).
- Создать каркас репозитория, `git init`, venv, `requirements.txt` с фиксированными версиями. Скопировать наработки из dota2-tierlist (оригинал не трогаю).
- **Проверка:** `python -m drafter.cli doctor` выводит версии, доступность OpenDota и Stratz, путь к Доте и её режим окна.

### Этап 1. Данные и модель
1. **Константы**: герои, предметы, способности, таланты, только активные facets, иконки, русские имена. Новый герой без русского имени даёт предупреждение.
2. **Сбор матчей**: Explorer, ranked All Pick, начиная с 7.41f, страницами по 50 тыс. Сбор можно продолжить после обрыва, вежливый темп (1 запрос в 2 с, укладываемся в лимиты). Фильтры: все 10 героев известны, длительность не меньше 15 минут (отсекаем ливы и ранние сдачи), без дублей. Запускается в фоне, я за ним не слежу.
3. **Stratz** (если будет токен): проверяю схему интроспекцией, потом выкачиваю по каждому герою позиции, предметы по фазам, прокачку, таланты, матчапы по брекетам. Кэш на патч.
4. **Позиции**: Stratz плюс EM-оценка по нашим матчам, сравниваю их между собой. Для подсказок герой считается играбельным на позиции, если `P(позиция | герой) ≥ 10%` на твоём брекете.
5. **Модель вероятности победы** (подробности ниже). Отчёт `reports/model.md`: сравнение с бейзлайном по стадиям драфта и брекетам, калибровочная кривая.
6. **Подбор героя под роль, подсказки по банам, объяснения.**
7. **Личные данные**: твоя история, пул героев и комфорт (винрейт сглаживается, чтобы 3 игры из 3 не выглядели как 100%), позиции в твоих матчах.
- **Проверка:** `cli collect`, `cli train`, `cli report`, `cli suggest --allies ... --enemies ... --pos 3` в консоли. Отчёт модели с цифрами.

### Этап 2. API бэкенда (FastAPI)
- `GET /heroes`, `GET /meta/tierlist?pos&bracket&days`, `GET /heroes/{id}` (матчапы, синергии, билды, моя статистика).
- `POST /draft/evaluate`: вероятность победы, доверительный интервал, вклад пар героев.
- `POST /draft/suggest`: топ-10 под мою позицию с причинами. `POST /draft/bans`.
- `GET /builds/{hero}?pos&bracket`, `POST /builds/{hero}/vs`: билд против драфта с причинами.
- `GET /me/*`, `POST /data/refresh` (задача «обновить после патча» с прогрессом), `GET /jobs/{id}`.
- `POST /gsi`, `WS /events` (стадия игры, мой герой, распознанный драфт → в интерфейс), `/vision/*`, `/settings`.
- Доступ только с 127.0.0.1 и только с токеном, который генерирует оболочка при запуске.
- **Проверка:** `pytest` (контракты, крайние случаи вроде пустого драфта или одного героя в двух слотах) плюс `/docs` (Swagger) в браузере.

### Этап 3. Основное окно и дизайн
- Страницы: **Драфт**, **Мета** (тир-лист), **Герой**, **Билды**, **Профиль**, **Настройки**.
- Драфт: 5+5 слотов и баны, выбор позиции 1–5, поиск по сленгу и с исправлением раскладки, горячие клавиши (`/` открывает поиск, `1–5` и `Shift+1–5` выбирают слот, `Del` очищает, `B` переключает на баны). Шкала вероятности победы с разбором пар. Топ-10 с причинами. Переключатель «учитывать мои комфортные пики».
- **Liquid Glass**: стеклянные панели (`backdrop-filter` с размытием и насыщенностью), преломление по краям через SVG-карту смещения из тир-листа, блики, мягкие тени, пружинные анимации (motion). Текст на стекле читается на любом фоне: подложка с затемнением под текстом и проверка контраста.
- **Фон**: встроенные градиенты и изображения, свой файл, ползунки размытия и затемнения.
- Тёмная и светлая тема, по умолчанию как в системе.
- Стек: React 19, TypeScript, Vite, Zustand, TanStack Query, motion.
- **Проверка:** запускаю окно, сам прохожу сценарий драфта, присылаю скриншоты обеих тем.

### Этап 4. Оверлей
- Второе окно: прозрачное, поверх всех, без рамки и без значка в панели задач. Acrylic размывает игру под окном. Если Acrylic недоступен, окно становится затемнённым полупрозрачным стеклом.
- Перетаскивание, изменение размера, ползунок прозрачности, запоминание позиции (window-state).
- Режим сквозных кликов. Глобальная клавиша показать или скрыть и вторая для включения взаимодействия. Обе настраиваются. Проверка конфликтов по твоим биндам Доты (их файлы только читаются).
- Если Дота в эксклюзивном полноэкранном режиме (`video.txt`, стиль окна), показывается подсказка, как переключить. Сейчас у тебя уже «окно без рамки».
- **Режим производительности**: во время игры отключаются размытие, преломление и анимации, обновления реже.
- Компактные режимы: «драфт» (вероятность победы, топ-5 под роль, баны) и «билд» (предметы против драфта).
- **Проверка:** оверлей поверх запущенной Доты, клики проходят сквозь, клавиши работают. Замер FPS в игре с оверлеем и без него.

### Этап 5. Game State Integration
- Установить свой конфиг GSI (с твоего согласия, вопрос 6) на отдельный порт с токеном.
- Сначала логгер: пишет всё, что приходит, на одном реальном матче или лобби с ботами. Так узнаем, приходит ли игроку блок `draft`.
- Логика: стадия выбора героев → показать оверлей в режиме драфта. Пик → подставить моего героя и сторону. Начало игры → режим билда против вражеского драфта плюс режим производительности. Конец матча → свернуть.
- **Проверка:** воспроизведение записанного лога GSI без игры (тест) и один живой матч.

### Этап 6. Чтение драфта с экрана (экспериментально, отключаемо)
- Захват только окна Доты (`windows-capture`, WGC), 1–2 кадра в секунду и только на стадии драфта по GSI. Бэкенд DPI-aware, у тебя масштаб 125%.
- **Мастер калибровки**: снимок экрана драфта → ты отмечаешь рамки слотов (готовые пресеты для 16:9 масштабируются под разрешение) → предпросмотр распознавания.
- **Распознавание**: нормализованная кросс-корреляция (OpenCV) по серому изображению и по цвету в каждой зоне, отдельно для пиков и для банов (у банов серые или перечёркнутые портреты).
- Шаблоны: портреты со Steam CDN плюс **вырезки из твоей игры**. Каждая твоя ручная правка сохраняет вырезку как эталон этого героя, и со временем точность растёт.
- Решение: порог уверенности плюс отрыв от второго кандидата плюс совпадение в 2 кадрах подряд. Иначе слот остаётся пустым. Ручная правка всегда важнее, распознавание её не перезаписывает.
- Стенд точности: папка с размеченными скриншотами → precision и recall по слотам → `reports/vision.md`. Включаем функцию, только если precision ≥ 98%.
- **Проверка:** отчёт точности на твоих скриншотах (вопрос 7) плюс живой драфт.

### Этап 7. Установщик
- Бэкенд собирается PyInstaller в один exe-sidecar, Tauri собирает установщик NSIS.
- Мастер первого запуска: аккаунт, токен Stratz, путь к Доте, GSI, оверлей.
- Кнопка «Обновить данные после патча»: константы → матчи с начала нового патча → Stratz → пересчёт модели → отчёт. Если матчей с начала патча ещё мало, предупреждает об этом.
- **Проверка:** установка на чистого пользователя Windows, запуск без dev-окружения.

## Модель

- **Данные**: ranked All Pick текущего патча, по умолчанию с 7.41f (порядка 3–5 млн матчей после фильтров, около 200 МБ Parquet). Брекет считается по `avg_rank_tier`.
- **Разбиение по времени**: обучение на старых днях, валидация на следующих, тест на последних 2 днях. Ничего из будущего не попадает в прошлое.
- **Бейзлайн**: `logit P(radiant) = c + Σ logit(wr героя Radiant) − Σ logit(wr героя Dire)` на твоём брекете.
- **Логистическая регрессия**: признак +1/−1 для каждого героя плюс суммы синергий союзных пар и контрпиков вражеских пар.
- **Синергии и контрпики** считаются **только на обучающей выборке**, со сглаживанием (empirical Bayes, у редких пар оценка тянется к нулю). Для строк самого обучения используется out-of-fold, иначе модель увидит ответ.
- **Бустинг** (LightGBM) на тех же агрегатах плюс брекет и признаки состава: покрытие позиций, доля магического урона и контроля.
- **Неполный драфт**: при обучении случайно скрываю часть героев, чтобы модель работала на 1v1, 3v3 и 4v5. Качество меряю отдельно для каждой стадии.
- **Калибровка**: Platt или isotonic на валидации. Метрики: log loss, Brier, ROC AUC, точность, ECE. Калибровочная кривая выводится в отчёт.
- **Честные ожидания**: по одному драфту в пабах исход предсказывается слабо. Типичный уровень — AUC около 0,58–0,62 и точность 55–58% на полном драфте. Прирост над бейзлайном измеряется в долях процента. Это будет в отчёте как есть, без подгонки. Ценность подсказок в относительном сравнении героев, а не в абсолютной цифре.
- **Подбор героя**: для каждого доступного героя на моей позиции считается `ΔP = P(победа | драфт + герой) − P(победа | драфт)`. Разбор: сила в мете на позиции и брекете, кого контрит (со вкладом каждого врага), с кем синергия, мой комфорт (если включено), **уязвимость к контрпику** (насколько популярные оставшиеся герои его контрят). Последнее важно при раннем пике.
- **Баны**: угроза героя = сила в мете на брекете плюс насколько он контрит уже взятых союзников (или мой пул, если союзников ещё нет) плюс герои, против которых я сам чаще проигрываю.

## Билд против драфта
- `hero_tags.yaml`: черновик собирается автоматически из данных способностей (тип урона, иллюзии, невидимость, лечение, призыв существ, сайленсы, пробивание BKB, развеиваемость), потом я вычищаю его вручную. Теги, например: `magic_burst`, `illusions`, `invis`, `heal`, `evasion`, `summons`, `physical_burst`, `lockdown`, `silence`, `armor_reduction`, `mana_burn`, `strong_passives`, `dispellable_buffs`.
- `build_rules.yaml`: условие по вражеским тегам → предметы → объяснение по-русски. Например: 3+ героя с магическим бурстом → BKB, Pipe, Eternal Shroud. Иллюзии → Mjollnir, Battle Fury, Shiva's. Невидимки → Dust, Sentry, Gem. Сильный хил → Spirit Vessel, Shiva's. Пассивки → Silver Edge. Уклонение → MKB, Bloodthorn.
- Рекомендации отбираются по моей позиции и по тому, что реально собирают на этом герое (данные Stratz), и сортируются по угрозе: вражеский кор важнее саппорта.
- Если Stratz отдаёт винрейт предмета по таймингу, он используется поверх правил. Винрейта предметов против конкретных героев в открытых данных не нашёл. Если найду, добавлю.

## Риски и ограничения
- **GSI**: блок `draft`, скорее всего, приходит только зрителю. Тогда драфт вводится вручную или читается с экрана. Проверим на этапе 5.
- **Stratz**: без токена позиции и билды будут слабее (EM-оценка позиций и про-билды OpenDota). Лимиты Stratz нужно проверить.
- **Immortal**: открытых данных нет, используем Divine.
- **Чтение экрана**: серая зона правил Valve, хоть память игры и не читается. Поэтому функция отключаемая, и захват идёт только на стадии драфта.
- **FPS**: Acrylic и анимации стоят GPU, поэтому есть режим производительности и замер на этапе 4.
- **Explorer OpenDota** — общий ресурс. Сбор идёт вежливо, а если explorer закроют, перейдём на `/publicMatches` (медленнее).

### Исправление билдов (17.10.2026)
- Главная причина: без `matchLimit` Stratz отбрасывал строки покупок по минутам с малым числом матчей. У саппортов и на редких позициях пропадали Blink, Glimmer, Aghanim's (у 56 сборок из 286 коровые были пустыми). Теперь запрос идёт с `matchLimit: 10`.

- Ситуативные предметы: без расходников и предметов с карты (Healing Lotus), без дешёвых предметов и без компонентов того, что уже есть в билде. Коровые: если от 25% игр набирается меньше трёх, добираются самые популярные от 10%.
- Страница «Билды» на позиции, где героя почти не играют, показывает билд основной позиции с пометкой.
- Итог проверки по всем 286 сборкам: пустых коровых 0 (у Chen 4 один предмет, там 283 матча за неделю), долей выше 100% нет. Таланты с «?» остались у Tinker и Naga: этих чисел нет в данных Valve.

### Этап 6 — готов, кроме замера на настоящем интерфейсе (17.10.2026)
- **Захват** (`vision/capture.py`): только окно «Dota 2» через Windows Graphics Capture, без рамки и курсора. Оверлей в кадр не попадает, масштаб Windows не сдвигает зоны. Разовый снимок занимает около 0,4 с; для чтения на стадии драфта сессия держится открытой. Если Доты нет, окно свёрнуто или игра в полноэкранном режиме, выдаётся понятная ошибка.

- **Распознавание** (`vision/matcher.py`, без нейросетей):
  - корреляция размытых серых изображений (устойчива к яркости, поэтому серые баны тоже находятся) плюс гистограмма цвета;

  - герой ставится, только если уверенность ≥ порога и отрыв от второго кандидата ≥ заданного, иначе слот остаётся пустым.
- **Фоновое чтение** (`vision/runner.py`): работает только на стадии выбора героев по GSI. Герой ставится после двух одинаковых кадров подряд и только когда известна сторона. Слоты, которые ты поправил руками, блокируются до следующего матча, а заполняются только пустые.
- **Мастер калибровки** («Настройки → Чтение драфта с экрана»):
  - снимок Доты, загрузка своего скриншота (F12 в Steam) или выбор сохранённого;
  - рамки перетаскиваются, размер меняется за уголок, есть режим «двигать группой», кнопка «Распределить» (ровно между первой и последней), «+/− бан», пресет;

### Бэкенд больше не переживает оболочку (18.10.2026)
- **Причина**: оболочка убивала бэкенд только при обычном выходе (`RunEvent::Exit`). Если `app.exe` завершался иначе (Диспетчер задач, падение, установщик при обновлении), `drafter-backend.exe` оставался сиротой, держал свои файлы, и обновление падало с «Невозможно открыть файл для записи». За два обновления у тебя набралось четыре таких процесса.
- **Исправлено в три слоя**:
  1. Job Object Windows с `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` (`backend.rs`, `windows-sys`). Дескриптор мы не закрываем, его закрывает Windows при завершении оболочки, как бы она ни завершилась, и тогда умирает всё в job, включая процессы, которые бэкенд запустил сам (в разработке это настоящий python за лаунчером venv).
  2. Сторож в Python (`drafter/api/__main__.py`): оболочка передаёт свой PID в `DRAFTER_PARENT_PID`, бэкенд ждёт завершения родителя через `WaitForSingleObject` и сразу выходит. Если родителя уже нет на старте, выходит сразу.
  3. Хук установщика (`app/src-tauri/windows/hooks.nsh`, `installerHooks`): перед установкой и удалением выполняется `taskkill /F /T /IM drafter-backend.exe` и пауза 1 с. Это закрывает сирот, оставшихся от старых версий, поэтому следующее обновление пройдёт без ошибки.
- **Проверено**:
  - Rust-тест: закрытие дескриптора job убивает дочерний процесс;
  - Python: бэкенд выходит через 0,1 с после смерти родителя, а с мёртвым родителем на старте выходит сразу;
  - релизный `app.exe` с временной папкой данных: после закрытия окна бэкенд исчез за 0,3 с, после `taskkill /F` по оболочке — за 0,2 с, сирот не осталось;
  - хук подключён в сгенерированном `installer.nsi`;
  - 67 тестов, cargo без предупреждений.
- **Не проверял**: сам хук в работе, потому что для этого нужно запустить установщик на твоём профиле.

- **Готовая статистика у Stratz.** Есть только исходы линии по парам (`heroStats.laneOutcome`), она уже используется. Поминутных агрегатов по парам у Stratz нет (проверил все поля `heroStats`), поэтому графики строятся по матчам.
- **Кнопка «Скачать данные линий»** (Настройки → «Данные линий»). Работает в фоне, с прогрессом, кнопкой «Остановить», ожиданием при исчерпании часового лимита (оставляет 400 запросов в час остальному) и продолжением с того же места.
  - Порядок: сначала герои пула (8 самых играемых, их основная позиция) против 12 самых частых соперников на главной позиции напротив и 5 на второй, затем частые пары коров (мид против мида, керри против оффлейнера).
  - Частота пары = совместные матчи нашей базы (Legend+) по разные стороны × доли героев на этих позициях.
  - *Решил сам*: качаю пары, которые вместе дают 50% всех встреч коров на линии (~630 пар). Все ~20 000 возможных пар заняли бы годы при дневном лимите 15 000 запросов. Сейчас в плане 761 пара: 131 для пула и 630 частых, по 60 матчей на пару (на экране пара догружается до 100), это примерно 3–4 дня работы.
  - Пары, где ожидается меньше 30 матчей, не качаются. Если матчей пары в базе нет совсем, выводится «пара слишком редкая». Исчерпанные пары помнятся неделю.
- Тесты: позиции и соседи по линии, порог вывода, план загрузки. Всего 70.

### 3. Чтение драфта с экрана: автосбор, разметка, автокалибровка, автовключение
- **Автосбор кадров** (`vision/collector.py`, вкл/выкл и лимит места в «Настройки → Чтение драфта с экрана»).
  - Когда GSI видит выбор героев или стратегию, раз в 3 с берётся кадр окна Доты. Сохраняется он, только если на верхней полосе (где пики и баны) изменилось ≥ 0,3% пикселей, то есть хотя бы один новый портрет. Не больше 25 кадров на драфт.
  - Кадры стадии стратегии помечаются «все герои».
  - Если включено фоновое чтение, сборщик берёт его кадры, а не захватывает окно второй раз.
  - *Решил сам*:
    - сбор включён по умолчанию;
    - лимит 500 МБ;
    - формат JPEG 95 (~0,6 МБ вместо ~3 МБ в PNG, на распознавание не влияет);
    - при превышении лимита удаляются самые старые драфты, текущий никогда.
  - Кадры лежат вместе со снимками мастера (`data/vision/snapshots/auto-*.jpg`), описание драфтов — в `data/vision/collected/`.
- **Разметка из твоих правок.** Составы с доски драфта, включая исправления после драфта, становятся разметкой кадров этого матча. Она обновляется во время драфта и игры и замораживается, когда матч заканчивается, так что очистка доски перед следующей игрой её не затрёт.
  - *Решил сам*: порядок слотов на доске может не совпадать с экраном, поэтому разметка хранится как состав команды (множество). Распознанный герой засчитывается, если он есть в этой команде.
  - Полнота считается только по кадрам «все герои» при полных составах 5 на 5.
- **Автокалибровка** (`vision/autocal.py`). По кадру с известными героями их портреты ищутся на верхней полосе шаблонным поиском в 16 размерах и 3 пропорциях. Находки должны лечь в один ряд, затем подбираются 5 равных слотов на команду (Dire зеркально).
  - На синтетике с рамками не там, где пресет: находит 10 из 10, читает 9 из 10 без ошибок, а пресет на том же кадре — 0.
  - Ручную калибровку автоматика не трогает. Автоматическую пересчитывает, только если она перестала находить 8 из 10 героев.
- **После каждого драфта** (`vision/auto.py`): автокалибровка, затем обучение шаблонов (вырезки команды сопоставляются её героям один к одному, сохраняются только уверенные), затем оценка точности.
  - Точность драфта считается без шаблонов, выученных на нём же, иначе она была бы завышена.
- **Автовключение.** *Решил сам*: функция включается сама при ≥ 2 драфтах, ≥ 10 кадрах, ≥ 30 распознанных героях и точности ≥ 98% (собранные кадры плюс подтверждённые в мастере). Если включилась сама, а точность потом упала ниже 98%, выключается. Если выключить вручную, сама больше не включится.
- **Мастер**: список «Кадры из твоих матчей» по драфтам, разметка выбранного кадра, кнопка «Автокалибровка по этому кадру» (рамки сначала показываются, сохраняешь сам), точность по подтверждённым кадрам, по матчам и общая, плюс условие автовключения.
- `PUT /settings` теперь меняет только присланные поля: старый клиент не сбросит новые настройки.
- Тесты: весь конвейер на синтетике (2 драфта, сохранение по изменению, разметка с доски в другом порядке, заморозка, автокалибровка, обучение, точность ≥ 98%, автовключение), лимит места, выключенный сбор, слияние настроек.

#### Что сделать тебе завтра (чтение драфта)
1. Проверь, что в «Настройки → Чтение драфта с экрана» включено «Собирать кадры драфта», и что GSI установлен (там же выше). Дота должна быть в окне или в окне без рамки, не в эксклюзивном полноэкранном режиме.
2. Сыграй 2–3 рейтинговых матча как обычно, но **заполни доску драфта в приложении**: свои и вражеские герои (баны необязательно). Можно во время драфта или после, хоть во время игры: исправления до конца матча тоже идут в разметку.
3. После второго матча загляни в мастер («Открыть мастер калибровки»): в «Кадрах из твоих матчей» должны быть драфты с пометкой «размечен». Нажми «Пересчитать точность».
   - Если точность ≥ 98%, функция включится сама (или включи переключателем).
   - Если ниже: открой кадр «все герои», нажми «Проверить распознавание», поправь ошибки кликом по рамке и нажми «Подтвердить кадр». Так шаблоны учатся на твоём экране.
4. Если автокалибровка не нашла портреты (в мастере «Не получилось: …»), пришли один кадр «все герои» (он лежит в `%LOCALAPPDATA%\DotaDrafter\data\vision\snapshots\auto-…jpg`): по нему подгоню поиск.

### 5. История матчей с оценкой игры
- «Профиль → Матчи» (вкладка рядом с «Пулом героев»): последние 30 рейтинговых матчей All Pick. В каждом: герой, позиция, результат, KDA, длительность, дата, метка и 2–4 причины с цифрами.
- **Данные** (`data/my_matches.py`): один запрос Stratz на 30 матчей. Он даёт твои показатели, `heroAverage` (средние героя на этой позиции и ранге по каждой минуте, это и есть норма), IMP, награду и исходы линий матча.
  - Stratz в списке матчей игрока отдаёт только самого игрока, поэтому состав команды (нетворс, IMP) догружается одним запросом на разобранный матч и хранится навсегда: разобранный матч не меняется.
  - Первая загрузка — около 25 запросов и 20 секунд, дальше только новые матчи. Обновление идёт в фоне раз в 20 минут при открытии вкладки, по кнопке «Обновить» и по «Обновить историю».
- **Оценка.** Основа — IMP Stratz (0 — обычная игра на этом герое).
  - *Решил сам*: «хорошо» от +10, «плохо» от −10. Разброс IMP около 25, так что это примерно трети.
  - Метка: результат × уровень игры: «вытащил», «выиграли вместе», «затащила команда», «проиграл, хотя сыграл хорошо», «проиграли вместе», «слил игру я».
  - *Решил сам*: вина и заслуга считаются относительно команды. «Слил игру я» — только если остальные сыграли заметно лучше (средний IMP остальных выше твоего больше чем на 10), иначе «проиграли вместе». Так же для «вытащил», «затащила команда», «проиграл, хотя сыграл хорошо». Без данных о команде метка ставится по одному IMP.
- **Причины.** IMP и два самых сильных отклонения от нормы в сторону метки:
  - показатели: нетворс к концу матча, опыт, ластхиты к 10-й минуте, смерти, урон по героям, урон по строениям, исход линии (из отчёта Stratz, с твоей стороны), место по нетворсу в команде с учётом позиции;
  - плюс средний IMP остальных, если метка про вину или заслугу.
  - *Решил сам*: каждое отклонение ограничено ±100%, веса: нетворс 1, опыт, ластхиты, урон по героям и смерти по 0,8, урон по строениям 0,5 (самый шумный).
- **Сводка сверху**: из поражений — в скольких скорее виноват ты, в скольких команда, в скольких вместе; то же для побед.
- Пометка внизу: оценка приблизительная, статистика не видит вижн, позиционку, сейвы и размены, особенно на саппортах.
- Неразобранные Stratz матчи показываются с пометкой «оценка появится позже».
- На твоих данных (30 матчей, 22 оценены): поражений 10 — на тебе 3, на команде 1, вместе 6; побед 12 — вытащил 4, вместе 6, затащила команда 2.
- Тесты: метки, причины и их направление, сторона линии, контекст команды, неразобранный матч, сводка. Всего 80.

### Линия в оверлее
- В режиме «Драфт» оверлея под составами появилась строка «Линия»: мой герой против вероятного соперника и вывод «ты фаворит, +N», «фаворит X, +N» или «примерно ровно». N — на сколько процентных пунктов эту линию чаще выигрывают, чем проигрывают (по Stratz). Под строкой тонкая полоса «выигрыш / ничья / проигрыш», в подсказке при наведении — точные доли и число линий.

- Мой герой берётся из GSI. Без GSI: единственный союзник или тот, по кому кликнул в составе (он подсвечивается).
- Попутно: число линий склоняется («163 линии»), добавлен общий `plural`.

### Иконки способностей и талантов в билдах
- **Прокачка** теперь полоса иконок способностей по уровням героя (1–16, 18, 20, 25…), номер уровня под иконкой. Цветное подчёркивание у каждой способности совпадает с легендой ниже, поэтому порядок читается с одного взгляда. На уровнях талантов стоит значок дерева талантов.
- **Подсказка при наведении** (и при фокусе с клавиатуры): русское название, короткое описание и «уровень N · так качают X% игр». Подсказка рисуется поверх всего окна (`Tip`, через портал), поэтому стекло панели её не обрезает и она не вылезает за край окна.
- **Таланты**: у каждого варианта иконка способности, которую он усиливает, или значок таланта, если талант общий (здоровье, урон). В подсказке: «Усиливает «Blink»» или «Общий талант», и сколько игр его берут.
- **В приблизительном билде** (порядок «первый уровень / максимум к») тоже иконки и подсказки.
- **Данные**: названия и описания — из русского фида Valve, который уже лежит в константах. Числа подставляются в описание («при 60% маны», «10 / 20 / 30 / 40»), разметка убирается, длинные описания обрезаются по концу предложения (до 220 знаков). Какую способность усиливает талант — тоже из фида: уникальный талант записан бонусом на своей способности.
- **Иконки** хранятся локально в `data/icons/abilities` и отдаются бэкендом. Недостающие докачиваются при первом показе билда (по 4–6 на героя), «Обновить данные после патча» качает все. *Решил сам*: при сохранении иконка уменьшается со 128 до 64 пикселей (на экране она 20–30 пикселей, запаса хватает и для масштаба 200%), поэтому весь кэш занимает 7 МБ вместо 24. У 49 врождённых способностей иконок на CDN нет — для них шестиугольный значок с буквами, как в игре.

Тесты: подстановка чисел и обрезка описания, способности и таланты Anti-Mage, отсутствие сети, когда скачивание выключено, способности в ответе билда. Всего 84, `tsc`.

### Переходы между вкладками: crossfade

## Баги после этапа 1 (19.10.2026)

### 1. Колесо мыши в настройках
- **Причина**: в браузере не воспроизводится ни при каком сочетании (масштаб 125%, снег, преломление, 1060×700 и 1380×880): у правой колонки настроек `overflow: auto`, обработчиков колеса в коде нет, у главного окна нет прозрачности и Acrylic. Значит, это поведение WebView2 на ПК пользователя, найти его точно без ПК нельзя.
- **Исправление**: страховка `app/src/lib/wheel.ts`. На каждое колесо ищется ближайшая область, которая может прокрутиться в эту сторону; если за 350 мс она не сдвинулась сама (нет события `scroll`), её прокручивает приложение и дальше делает это сразу. Область, которая двигается сама, запоминается и не трогается — двойной прокрутки нет (проверено в Chromium: синтетическое колесо → прокрутка нашей страховкой, настоящее → только родная прокрутка).
- **Отладка**: Ctrl+Alt+Shift+W включает запись каждого колеса в `%LOCALAPPDATA%\DotaDrafter\logs\ui-debug.log` (элемент под курсором, какая область должна прокрутиться, сдвинулась ли сама, помогли ли мы); в углу окна плашка «Отладка колеса включена». Бэкенд: `POST /debug/log` (2 теста, файл не растёт больше 2 МБ).
- Решено самостоятельно: порог 350 мс — медленный, но рабочий движок успевает прислать `scroll`, а сломанное место прокрутится с задержкой только первый раз.

### 2. Калибровка: рамки «ломаются»
- **Причина**: в режиме «Двигать и менять размер группой» уголок менял ширину и высоту каждой рамки, а их места оставались прежними — рамки наезжали друг на друга и на соседние портреты. Пересчёт координат проверен и верен: превью и чтение используют один и тот же кадр окна Доты (WGC-захват окна в реальных пикселях — при 125% это 2560×1440) и одни и те же доли его размеров; окно без рамки на это не влияет, кроме случая, когда кадр снят с рамкой (теперь об этом предупреждение).
- **Исправление**: `app/src/lib/calibrate.ts` — группа масштабируется от своего левого верхнего угла, расстояния растут вместе с рамками, за кадр не выходит (4 теста). Под кадром полоса «Что вырезается»: бэкенд режет кадр тем же кодом, что и чтение (`POST /vision/crops`, 2 теста, в т.ч. 2560×1440). Вид «Рамки крупно» по умолчанию.
- Проверено в браузере на синтетическом кадре 2560×1440 при масштабе 1.25: рамки не наезжают, 10 вырезок видны сразу.

### 5. Своя иконка приложения везде
- **Причина**: картинка ставилась только главному окну и только из интерфейса (`setIcon` после загрузки страницы); оверлей, трей и ярлыки оставались со стандартной. Значок закреплённого на панели задач приложения Windows берёт из ярлыка, а не из окна, поэтому на панели он не менялся.
- **Исправление**: `src-tauri/src/appicon.rs`. Интерфейс один раз делает из картинки PNG 256 и `.ico` на 10 размеров 16–256 (`lib/ico.ts`, 2 теста; файл проверен PIL: все размеры читаются) и отдаёт оболочке. Оболочка кладёт их в `%LOCALAPPDATA%\DotaDrafter\icon`, ставит значок всем окнам (главное и оверлей — панель задач, Alt+Tab) и трею, а нашим ярлыкам (`.lnk`, чья цель — наш exe) на рабочем столе, в «Пуске» и закреплённым на панели задач меняет значок на этот `.ico` через WScript.Shell в PowerShell и просит Проводник перерисовать значки. При каждом запуске значок ставится до показа интерфейса, ярлыки проверяются в фоне — установщик новой версии пересоздаёт их со стандартным значком. «Вернуть стандартную» удаляет файлы и возвращает ярлыкам значок exe.

- Проверено: `cargo check --target x86_64-pc-windows-msvc` без предупреждений, кодировщик base64 для PowerShell — тест против известных значений и Python, `tsc`, `npm test`. **Не проверено из облака**: сам вызов PowerShell и вид значков в Windows.

### 3. Игры топов — вкладка сделана целиком
- **Откуда матчи.** Публичного «последние матчи героя на высоком ранге» у Stratz нет (`matches(ids)` только для админов), поэтому:
  - «Immortal» и «Divine+»: `leaderboard.hero` (100 лучших игроков на герое в своей лиге) → `player.matches` самых активных из них на этом герое. Берутся только матчи текущего патча и не ниже ранга лиги. Оба запроса проверены на настоящем Stratz.
  - «Про»: OpenDota `/heroes/{id}/matches` → `/matches/{id}` (до 24 разборов за загрузку); позиция — по линии и богатству (на линии из двух богаче — кор).
- **Запросы и лимиты.** Не больше 16 запросов Stratz за загрузку (лидерборд + 15 игроков по 6 матчей, цель — 60 матчей), шаг 0,45 с (лимит 8/с). Если в часовом лимите токена осталось ≤ 60 — останавливается и пишет почему: запас для остальных вкладок. Загрузка в фоне, матчи появляются по мере прихода (список обновляется каждые 2 с). Кэш `data/topgames/<источник>/<герой>.json`; при открытии — сразу из кэша, новая загрузка не чаще раза в 6 часов или по кнопке «Обновить». Ошибки по-русски: нет токена, токен не принят, лимит Stratz, лимит OpenDota, сеть.
- **Что в матче.** Исход, KDA, NW, LH/DN, GPM/XPM, длительность, урон, итоговые предметы и нейтралка; раскрытие — покупки с таймингами (иконки), прокачка по уровням (иконки, таланты текстом), кривая NW по минутам (у про — золото), союзники и враги, ссылка на Stratz.
- **Сводка сверху** (по отфильтрованным матчам): число матчей, винрейт, медианная длительность, медианные тайминги ключевых предметов (собранные от 1400 золота, плюс Blink и Shard) с долей матчей, самые частые сборки из первых трёх ключевых предметов с их винрейтом.
- **Фильтры**: источник (ранг), позиция, «Только победы», «Против героя». Игроки текущего матча не подтягиваются никогда — вкладка знает только героя, которого выбрал пользователь.
- **Решено самостоятельно.** Необязательные поля Stratz (KDA и прочие цифры, итоговые предметы, кривая NW, исход) запрашиваются группами: если Stratz ответит «Cannot query field», группа отключается и запрос повторяется без неё — вкладка работает и при смене схемы, просто без этих колонок. Основа (герой, игрок, победа, позиция, покупки, прокачка) проверена вживую.
- **Проверено.** Бэкенд — 6 тестов (разбор Stratz и OpenDota, отключение неизвестного поля с повтором, другие ошибки не глотаются, кэш и фоновая загрузка, отсев прошлого патча, ошибки в сообщения); интерфейс — 3 теста (фильтры, тайминги, сводка); в браузере на подставном кэше: поиск героя, сводка, список, раскрытие (покупки, прокачка, кривая), все фильтры, окно 1060×700; без сети «Про» показывает понятную ошибку. **Не проверено из облака**: Stratz отсюда недоступен, поэтому необязательные поля на живой схеме не проверены (на этот случай и сделан откат по группам).

### 4. Чтение драфта без калибровки
- **Как Дота масштабирует интерфейс.** Panorama считает размеры в единицах 1/1080 высоты окна: на 1080p, 1440p и 2160p одна и та же панель занимает одну и ту же долю высоты. Верхняя полоса выбора привязана к центру, поэтому на 16:10 и 21:9 она стоит на том же числе «единиц высоты» от центра, а по бокам просто больше места. Поэтому раскладка хранится один раз — в этих единицах от центра (`backend/drafter/vision/layout.py`) — и пересчитывается в доли окна под любой кадр. Встроенные профили для 1920×1080, 2560×1440, 3840×2160, 1920×1200, 2560×1600, 2560×1080 и 3440×1440 — это одна формула; прочие разрешения считаются так же.
- **Откуда цифры.** Старый пресет описывал верхнюю панель самой игры и в драфте 7.41 был мимо (слот 58 px на 1080p вместо 107). Новая раскладка измерена по кадру 2560×1440 из твоей игры (мастер, стадия стратегии, рейтинговый All Pick): слот Dire k — левый край 146 + 123·k единиц от центра, ширина 107, арт с 5 по 65 сверху; Radiant — зеркально. Точность ±3 единицы, остальное подгоняет автоопределение. Твои сохранённые рамки (ручные или найденные по кадру с героями) сами становятся раскладкой: на кадрах с другим соотношением сторон они пересчитываются, а не растягиваются.
- **Автоопределение** (`layout.detect`, героев знать не нужно). По кадру, где выбрано хотя бы 4 героя, подбираются масштаб (0,8–1,25) и сдвиг полосы (±3% ширины, вниз до 4% высоты): на каждом варианте слоты вырезаются и сравниваются со всеми портретами. Побеждает вариант, где вырезки сильнее всего похожи на героев (пустые слоты считаются нулём, поэтому съехавшие на фон рамки не выигрывают). Сначала грубо, потом с шагом в 1–2 пикселя, около 2 с на кадр. Во время драфта это происходит само: чтение берёт первые подходящие кадры (не чаще раза в 15 с, пока не получится), найденное сохраняется для этого разрешения (`data/vision/layout.json`) и сразу используется.
- **Порядок рамок для кадра** (`layout.for_frame`): ручные рамки этого соотношения сторон → найденные по кадру с известными героями (автокалибровка после драфта, как раньше) → подгонка встроенного профиля под это разрешение → сам профиль (или пересчитанные твои рамки).
- **Режимы окна и масштаб Windows.** Захват окна (WGC) идёт в физических пикселях, поэтому масштаб 100–175% на кадр не влияет. В оконном режиме кадр раньше содержал заголовок и рамки окна: теперь клиентская область вырезается по данным Windows (`capture.client_crop`, запрос в режиме per-monitor DPI, поэтому в тех же физических пикселях). Окно без рамки и полноэкранный режим — без изменений. Эксклюзивный полноэкранный режим WGC не захватывает, как и раньше (понятная ошибка).
- **Шаблоны портретов — в самой программе**: `shared/hero-templates/` (127 горизонтальных портретов Valve 192×108, 1,3 МБ) одинаковы у всех и лежат в установщике, а не в пользовательских данных. Скачанная иконка нужна только героям новее программы. Выученные вырезки из твоей игры добавляются к ним, как раньше. Проверено: все тесты чтения проходят с убранной папкой `data/icons/heroes`.
- **Мастер** («Настройки → Чтение драфта → Проверить чтение»): у кадра показаны рамки, которые чтение возьмёт для его размера, и откуда они. Есть «Найти рамки по кадру» (подгонка без героев, сохраняется для этого разрешения), «Встроенный профиль», «Сбросить на автоматические» (забыть ручные и найденные рамки) и раскрывающееся «Как проверить». Ручная калибровка осталась запасным путём: «Сохранить рамки» делает рамки ручными.
- **Решено самостоятельно:**
  - баны в профиль не добавлены: на экране драфта 7.41 я их не измерил, а угадывать не стал; рамки банов, если нужны, ставятся руками, как раньше;
  - 4:3 не в списке профилей: там Дота ужимает полосу по-своему. Автоопределение (масштаб до 0,8) должно справиться, но это не проверено.
- **Проверено:**
  - 9 новых тестов: одна раскладка на все 16:9, зеркальность, перенос ручных рамок на 21:9 без искажений; подгонка масштаба и сдвига на 2560×1440, 1920×1200 и 3440×1440 (масштаб точнее 1,5%, сдвиг — 10% слота) и чтение всех героев после неё; отказ на кадре без портретов и на шуме; сама подгонка в цикле чтения; вырезка клиентской области; API мастера. Старые тесты чтения проходят без изменений.
  - Отдельно на кадрах, похожих на настоящие (подпись ранга поверх портрета, скошенный край, цветная полоса команды, часы): масштаб находится с точностью 0,5%. Без выученных шаблонов читается 8 из 10, два слота остаются пустыми, неверных героев нет.
  - В браузере: мастер на кадре 2560×1440 → «Найти рамки по кадру» → рамки на портретах, все 10 вырезок верные.
  - **Не проверено из облака:** настоящая Дота на других разрешениях и в оконном режиме (вырезка рамки окна — Win32, работает только на Windows).

### 5. Матчи без разбора: запрос разбора, перепроверка, упрощённая оценка
- **Запрос разбора.** У OpenDota он официальный: `POST /request/{match_id}` → `{job: {jobId}}`, `GET /request/{jobId}` возвращает задачу, пока она в очереди, и `null`, когда она закончилась; удалось ли разобрать запись, видно по полю `version` в `/matches/{id}` (сверено по исходникам OpenDota, `svc/api/spec.ts`). Один такой запрос OpenDota считает за 10 обычных, поэтому за одно обновление уходит не больше 3. У Stratz в документации запроса на разбор нет: рейтинговые матчи он разбирает сам. Проверить его схему из облака нельзя (Stratz отсюда недоступен), поэтому программа на твоём ПК раз в неделю ищет в схеме API Stratz мутации со словами «parse / retry / replay» и пишет под историей матчей, что нашла. Найденное не вызывается вслепую.
- **Перепроверка.** Пока хоть один матч ждёт разбора, история обновляется из Stratz каждые 5 минут (а не 20) — и в фоне, и пока открыт профиль. Задача OpenDota проверяется не чаще раза в 10 минут. Если OpenDota разобрал запись, ждём Stratz. Если не смог (записи нет, матч не найден) — матч сразу получает упрощённую оценку. Если Stratz не разобрал матч за сутки после его окончания — тоже упрощённая. Как только Stratz разберёт матч, оценка становится полной сама.
- **Упрощённая оценка** (`my_matches.simplified`) — по тому, что есть у любого матча без записи. Против нормы героя от Stratz: нетворс, опыт, ластхиты, урон по героям, убийства+помощь, смерти. Если нормы нет — против процентилей OpenDota по герою и роли (`/benchmarks`, кэш на 3 дня): GPM, XPM, ластхиты, урон и убийства в минуту. У саппортов фарм весит вдвое меньше. Среднее отклонение от +0,25 — «хорошо», от −0,25 — «плохо», ярлык тот же, что у полной оценки, с первой причиной «упрощённая оценка: матч без разбора записи». Состава команды у такого матча нет, поэтому вина и заслуга не делятся с командой.
- **В истории** у каждого матча статус «разобран / в очереди / упрощённая», в строке сверху — сколько каких, у матча в очереди — когда ушёл запрос. Пояснение под списком.
- **Исправлено попутно:** отклонённый OpenDota запрос на разбор не учитывался в лимите запросов за обновление.
- **Проверено:**
  - 13 тестов истории (было 6):
    - упрощённая оценка по норме Stratz и по процентилям OpenDota, мягче для саппортов;
    - нечего сравнивать — понятное сообщение;
    - статусы по времени и состоянию разбора;
    - запросы на разбор: не больше 3 за раз, никогда дважды для одного матча, отказ даёт «недоступна», законченная задача с записью — «ждём Stratz»;
    - процентили качаются только для упрощённых матчей;
    - перепроверка раз в 5 минут, только пока есть ждущие;
    - поиск запроса разбора в схеме Stratz.
  - В браузере на подставной истории три матча с тремя статусами.
  - **Не проверено из облака:** живые OpenDota и Stratz (оба отсюда недоступны).

### 6. Портреты героев: только модель, на прозрачном фоне
- **Откуда был фон.** Страница героя и баннер брали `…/dota_react/heroes/renders/<герой>.png` — это неподвижный кадр рендера со сценой за моделью, отсюда «свой фон». Без фона у Valve только анимированный рендер `…/renders/<герой>.webm`, который показывает dota2.com: VP9 с альфа-каналом (адрес подтверждён по открытым проектам, которые его используют). Отдельной PNG без фона на CDN нет.
- **Как сделано** (`backend/drafter/data/renders.py`, `app/src/components/HeroModel.tsx`):
  - при первом показе героя бэкенд один раз скачивает его webm (5–10 МБ) в `data/icons/renders`;
  - приложение (WebView2 декодирует альфу VP9) рисует первый кадр на холсте, проверяет, что это настоящая вырезка (прозрачные края, плотная модель), и отправляет PNG бэкенду;
  - бэкенд проверяет то же самое, обрезает пустые поля, считает цвет героя для свечения (самый частый насыщенный оттенок модели, высветленный) и кэширует;
  - дальше всегда показывается кэш, без сети;
  - на странице героя поверх картинки играет сам рендер (анимация как на dota2.com): видео ставится ровно туда же, где стоит картинка (по сохранённой рамке обрезки), поэтому модель не прыгает, когда видео начинает играть.
- **Если рендера без фона нет** (новый герой, видео нет на CDN или оно не декодировалось) — фон убирается локально один раз: GrabCut по кадру со сценой (или по иконке), края — фон, центр — модель, берётся самый большой кусок, края смягчаются. Результат помечается «segmented» и кэшируется так же.
- **Подложка:** тот же герой, вертикальный портрет, размытый и насыщенный; мягкое радиальное свечение в цвет героя; стеклянная кромка (светлая сверху, цветная снизу, блик наискосок) и цветная тень. Карточка начинается на 13% ниже рамки, поэтому голова модели выходит за её верх, а ноги обрезаются по скруглённому низу. Пока модель готовится, подложка мягко пульсирует (выключено при «уменьшить движение»).
- **Где:** карточка на странице героя (с анимацией) и баннер профиля с героем: размытая сцена героя фоном, свечение, модель стоит справа, её можно двигать мышью влево и вправо. Обои окна по-прежнему используют кадр со сценой: для обоев сцена и нужна.
- **Проверено:**

### 7. Данные линий: графики по запросу, фоновое скачивание — только пул и по желанию
- **Что было.** Графики по минутам строились по 100 матчам пары, один запрос Stratz на матч. Поэтому их предлагалось качать заранее для 751 пары, а это дни работы.
- **Вердикт «кто выигрывает линию»** не менялся: агрегат Stratz, один запрос на героя и позицию (все его соперники сразу), кэш на 3 дня.
- **Графики — по запросу, пакетами** (`lane/pairs.py`). Когда открываешь пару, грузится 25 её матчей (графики появляются с 20). Пакетного `matches(ids)` у Stratz для обычных токенов нет, поэтому пакет — это один GraphQL-запрос с несколькими `match(id)` под псевдонимами (`m0: match(id: …) m1: …`), а лимиты токена считают это одним запросом. Сколько матчей помещается в запрос, Stratz не документирует. Поэтому пакет начинается с 10 и растёт на 5 после каждого удачного ответа (до 30). Если Stratz отклонит запрос как слишком сложный, пакет уменьшается вдвое, а предел запоминается (`data/stratz/lane_pairs/batch.json`) и показывается в настройках. Матч, которого у Stratz нет, приходит пустым и не портит остальные (`Stratz.q_all`: данные и ошибки отдельно). Размер следующего пакета считается по доле подходящих матчей этой пары (оба на одной линии на нужных позициях). Прогресс показывает матчи и потраченные запросы. Повторное открытие — из кэша, без запросов.
- **Сколько запросов на пару.**
  - Вердикт — 1 запрос на героя и позицию, общий для всех его соперников, раз в 3 дня.
  - Графики: подходят примерно 40–60% матчей пары из базы, так что на 25 подходящих нужно 45–65 матчей. При пакете 10→15→20→25 это 3–4 запроса, при пределе Stratz в 10 матчей — 5–7. Больше 12 запросов на пару не уходит никогда (было около 100–300).
  - Повторное открытие — 0 запросов.
- **Фоновое скачивание** (`lane/bulk.py`) осталось опцией. По умолчанию выключено, запускается только кнопкой «Скачать пары моего пула», качает только пары твоего пула (8 самых частых героев на их позиции против частых соперников на линии) по те же 25 матчей. Частые пары чужих героев больше не качаются. Продолжение после перезапуска и запас лимита для остального — как раньше.
- **Проверено:**
  - 2 новых теста пакетов на подставном Stratz (отказ больше 8 матчей): 25 матчей приходят все и по порядку, один отсутствующий не портит остальные, пакет уменьшается после отказа и больше его не превышает, 40 матчей — за 5 запросов; 25 подходящих матчей — не больше 4 запросов, прогресс, повторное открытие без запросов;
  - план фонового скачивания — только пул;
  - тест продолжения после перезапуска не изменился и проходит;
  - карточка в настройках в браузере.
  - **Не проверено из облака:** настоящий предел Stratz на число матчей в запросе (программа узнает его сама при первой загрузке и покажет в настройках).

### Чтение драфта включено сразу и учится само (по просьбе пользователя, 19.10.2026)
- **Что было:** чтение включалось только после доказанной точности ≥ 98% (3 подтверждённых кадра в мастере или 2 драфта с заполненной доской). У пользователя: 6 кадров в мастере (100%), 99 кадров из 4 драфтов, «64,7%», полнота «—». Полнота «—» значит, что ни в одном драфте на доске не было всех 10 героев.
- **Ошибка в подсчёте точности:** верно прочитанный герой, которого пользователь не вписал на доску, считался ошибкой. Поэтому 64,7% было сильно занижено. Теперь герой считается ошибкой, только когда доска это доказывает: он в другой команде или в банах, или его команда на доске полная (5) и без него. Остальные идут в «неизвестно» и в точность не входят (`evaluate.evaluate_collected`, поле `unknown`).
- **Включено сразу:** настройка `vision_off` («выключено вручную», по умолчанию нет) вместо `vision_enabled`, проверки точности при включении больше нет. Кто раньше выключил чтение в мастере (`manual_off`), остаётся с выключенным. Автоматического выключения больше нет: выключает только пользователь.
- **Осторожный режим** (`runner.CAUTIOUS_*`), пока точность не подтверждена: порог уверенности не ниже 0,62, отрыв от второго кандидата не ниже 0,10, слот заполняется после 3 одинаковых кадров вместо 2. Лучше пустой слот, чем чужой герой. Когда после драфта `good_enough` (2 драфта, 10 кадров, 30 героев, 98%), режим снимается сам (`auto.finalize` → `proven`); если точность упадёт — возвращается.
- **Обучение** как было: после каждого драфта вырезки сопоставляются героям с итоговой доски (вписанным программой и исправленным пользователем) и сохраняются как шаблоны его экрана. Подтверждение кадров в мастере теперь необязательно.
- **Интерфейс:** в карточке настроек — переключатель «Читать драфт с экрана», статус «учится / включено» и сколько осталось до снятия осторожности. В мастере те же слова, без «нужно 98% на 3 кадрах».
- **Проверено:** 2 новых теста (неполная доска не делает верные чтения ошибками; осторожный режим ждёт третий кадр и не смелее обычного) и обновлённый сквозной тест (2 драфта → «confident»). Все тесты чтения проходят. В браузере: по умолчанию включено, «учится», переключатель и пояснение в карточке.

### Чтение экрана: союзники читались, враги — никогда
- **Причина:** у игрока GSI присылает блок драфта только своей команды. Трекер (`backend/drafter/gsi.py`) на каждом сообщении переписывал обе команды целиком: союзников — из блока (поэтому они были «идеальными», это не чтение экрана), а врагов — пустыми слотами. Враги, которых только что поставило чтение экрана, стирались через секунду, а чтение экрана считало стёртый слот правкой пользователя и больше его не трогало до следующего матча.
- **Исправлено:** блок драфта теперь сливается с доской (`merge_slots`): герои из блока добавляются в пустые слоты, герой убирается, только если Дота показала его в другой команде, а слоты, которых в блоке нет, не трогаются. Баны только добавляются. Если ничего не поменялось, ничего и не отправляется.
- **Проверено:** 2 новых теста (блок только своей команды не стирает врагов, повтор того же блока ничего не меняет; правила слияния), весь набор — 197 прошло.
- **Не проверено из облака:** живая Дота. Если враги всё равно не заполнятся, нужен журнал GSI с ПК: `%LOCALAPPDATA%\DotaDrafter\data\gsi\*.jsonl`.

### Полоса в стекле на вкладке «Герои»
- **Причина:** у анимированной модели героя область обрезки (и тени) поднималась на 50% своей высоты над карточкой, то есть почти до верха окна, под таблетку вкладок (проверено по разметке: модель с 140 px, обрезка с ~20 px, вкладки 11–61 px). Каждый кадр видео перерисовывал эту область, и стекло вкладок над ней пересчитывалось кусками — отсюда дёргающаяся светлая полоса, только на «Героях» (только там играет видео модели).
- **Исправлено:** голова может выходить над карточкой только в пределах своего блока (там и так оставлено 13% высоты под это), выше обрезки нет. Визуально модель не изменилась.
- **Не проверено из облака:** сам артефакт виден только на видеокарте в WebView2; в облаке Chromium рисует программно.

- Новая вкладка между «Играми топов» и «Оформлением» (Ctrl+5; настройки теперь Ctrl+8). Слева — патчи от нового к старому с датой, числом изменённых героев и предметов и звёздочкой с числом изменённых *твоих* героев; справа — выбранный патч: «Всё / Мои герои / Герои / Предметы / Общее», поиск по имени героя (и русскому), предмета или слову. Герои: их собственные строки, способности со значком, таланты; твои герои — первыми и с пометкой «твой», полоска «Изменились твои герои» с переходом к карточке. Клик по герою — его страница.

Скачивается не чаще раза в сутки (кнопка ↻ — сразу), хранится в `data/patchnotes`; без сети показывается последняя копия. Файлы Доты на ПК не читаются. - **Проверено:** 4 теста (порядок версий, группировка и очистка, мои герои первыми, последняя копия без сети, API); в браузере на настоящем файле.

### Подсказки во время игры (оверлей)
- В режиме «Билд» оверлея во время матча сверху блок «Сейчас · 13:02» (раз в секунду, только по GSI — то, что Дота присылает сама; `backend/drafter/ingame.py`, `GET /game/live`):

  - **таймеры** ближайших четырёх событий: руна силы (с 6:00 каждые 2 мин), руны воды (2:00 и 4:00), руны богатства (каждые 3 мин), руны мудрости (с 7:00 каждые 7 мин), лотосы (каждые 3 мин), смена дня и ночи (каждые 5 мин, по флагу дня из GSI); меньше 15 с — подсвечено. Правила карты сверены с патчноутами 7.33–7.41f (последние изменения таймеров — 7.33);

### Драфт с экрана: слоты по цветным полоскам игроков (без калибровки)
- **Почему не находились враги.** Слоты брались по встроенной раскладке (единицы 1/1080 высоты от центра) с подгонкой масштаба 0,8–1,25. На скриншоте пользователя (2000×840) портреты оказались другого размера и места: рамки легли на края и щели между портретами, и большинство слотов не проходило осторожный порог. Союзники при этом были полными, потому что их присылает GSI. Если те же портреты вырезать точно, шаблоны узнают врагов: Dragon Knight, Winter Wyvern, Wraith King, Earthshaker и Silencer (у последнего оценка ниже порога), союзников тоже. Значит, ошибались рамки, а не распознавание.
- **Что сделано** (`backend/drafter/vision/bars.py`). Над каждым портретом верхней панели Доты есть тонкая полоска цвета игрока. Это самые насыщенные «ровные» строки в самом верху окна, все одной ширины и с одним шагом. Программа ищет строки, где цвет разбит на несколько длинных чистых отрезков (портреты ниже пёстрые и дробят их), и берёт по ним столбцы. По найденным отрезкам подбирается сетка 5 + 5 слотов, симметричная вокруг часов: шаг — медиана расстояний, ширина — медиана ширины. Недостающую полоску (например, не нарисованную) сетка достраивает сама. Портрет — прямо под полоской, высотой 0,6 ширины, с отступом от скошенных краёв. От разрешения, соотношения сторон, масштаба интерфейса и размера окна это не зависит, калибровка не нужна.
- Чтение экрана сначала ищет слоты по полоскам и только если полосок нет (не экран драфта) берёт старую раскладку. Пороги осторожного режима для слотов по полоскам: уверенность 0,5, отрыв 0,08: при точных рамках правильный герой ведёт с явным отрывом, хотя абсолютная оценка ниже из-за скоса портрета. Ручная калибровка теперь не нужна; полоски главнее.
- **Проверено:** 10 тестов: слоты на 6 разных экранах (1080p, 1440p, 21:9, 3440×1440, 720p, 16:10), достраивание пропавшей полоски, «нет полосок — нет слотов», на кадре пользователя (верх панели без ников) — все 10 слотов на месте, враги 4 из 5 и союзники 4 из 5 (пятый — Anti-Mage в образе «Вэй», он приходит из GSI). Весь набор: 233 прошло.

### Стекло без полос и подлагиваний, материалы панелей
- **Причина полос и мигания.** Стекло было живым `backdrop-filter`: на каждом кадре, где что-то движется (снег и другие эффекты фона, видеообои, модель героя, переходы), WebView2 заново размывает то, что под панелью, и делает это кусками. Отсюда светлые полосы, которые дёргаются (на «Героях», а потом и на «Мете» под панелью вкладок), и подлагивания: размытие пересчитывалось на всех панелях постоянно. Причём это не баг одной вкладки.
- **Что сделано** (`app/src/lib/glassBackdrop.ts`, `glass.css`). Панели лежат прямо на обоях, поэтому то же размытие считается один раз: обои уменьшаются до 320 px по ширине, размываются и насыщаются на canvas и стоят под каждой панелью фиксированным фоном, совпадающим с обоями. Тон, блик и кромка панели — слоем поверх, затемнение обоев учитывается. Градиентные обои идут как есть (они и так мягкие). Видеообои переразмываются 2 раза в секунду и стоят на месте, когда видео на паузе. Если картинку нельзя прочитать (арт героя с CDN без разрешения), остаётся прежнее живое размытие. Живое преломление по краям тоже требует живого размытия, поэтому теперь оно выключено по умолчанию (миграция настроек) и подписано, что на некоторых видеокартах мерцает.
- **Материал панелей** (Настройки → Оформление): «Жидкое стекло» (как было, прозрачное с бликом), «Матовое» (сильное размытие, почти непрозрачное), «Акрил» (как в Windows 11: цвет обоев, тон и мелкое зерно), «Как в Доте» (плотные графитовые панели с тонкой кромкой и острыми углами, обои сквозь них не видны). У каждого своя светлая тема.
- Синяя рамка вокруг активной вкладки после клика (кольцо фокуса) теперь появляется только при работе с клавиатуры (Tab).

### Превью шрифта: «Шрифт Доты»
- **Почему было не так.** В списке шрифтов первым и выбранным по умолчанию стоял Libre Franklin, поэтому превью сразу показывало чужой шрифт. Пункта «как в Доте сейчас» не было, а сетка героев в превью рисовалась шрифтом программы.
- **Что сделано.** Первый пункт и выбор по умолчанию — «Шрифт Доты». С ним сцены меню и матча показывают текст в пикселях самой игры, а подписи сетки героев рисуются Radiance SemiBold. Кнопка «Вернуть шрифт Доты» активна, если шрифт был заменён (возвращает оригиналы из резервной копии).
- Шрифты Доты Radiance и Reaver с кириллицей лежат в программе (`app/public/dota-game-fonts`, README). Взяты из открытого репозитория GridStudio, где они нужны для того же превью. По лицензии в самих файлах Valve разрешает фан-арт. В Доту они не ставятся, только показываются. Ими же теперь рисуются названия групп в редакторе сеток: арт там посчитан по ширинам Radiance, так что выглядит как в игре.

### Тема применялась с опозданием на шаг
- **Почему.** Затемнение стекла под тёмную тему (`--veil`) выставлял фон окна, а он узнавал тему, читая `<html data-theme>`. Эффект фона срабатывает раньше эффекта приложения, который меняет `data-theme`, поэтому фон всегда видел прошлую тему: светлая тема с тёмным затемнением выглядела серой, а следующее переключение показывало предыдущую.
- **Что сделано.** Видимая тема считается из самой настройки (и системной темы Windows для «Как в системе») хуком `useResolvedTheme` (`app/src/lib/theme.ts`), им пользуются и приложение, и фон.
- **Проверено** в браузере: светлая → тёмная → светлая → системная → тёмная, `data-theme` и затемнение совпадают на каждом шаге.

### Иконка «DM» (Drafter Manager)
- Монограмма по наброску пользователя: D сверху слева, M ниже и правее, её левая ножка начинается внутри чаши D, а средняя диагональ пересекает её. Ровные скруглённые линии, белые с лёгким голубоватым градиентом, M чуть прозрачнее, чтобы перекрытие читалось. Стиль прежний, Liquid Glass: размытые цветные пятна, стеклянная линза с бликом и светлой кромкой.
- Обновлены иконки приложения (все размеры, `.ico`, `npx tauri icon`), логотип в шапке (`public/brand.svg`), исходник `app/design/app-icon.svg` и картинки установщика NSIS.
- **Проверено:** отрисовка в 1024 и 32 px, картинки установщика.

### Оверлей: закруглённые углы
- **Почему торчали углы.** Страница оверлея прозрачная и скруглена (26 px), но системный Acrylic размывает всё прямоугольное окно, поэтому за скруглением были видны квадратные углы размытия.
- **Что сделано.** Окно оверлея обрезается по той же скруглённой форме (область окна Windows, `SetWindowRgn` + `CreateRoundRectRgn`, `overlay_round` → `round_corners` в `overlay.rs`): при запуске, при каждом изменении размера (в том числе свёрнутая таблетка) и при смене масштаба экрана. Радиус в физических пикселях считается от масштаба. Оверлей теперь понимает тему «Как в системе».
- **Проверено:** `cargo check` под Windows. **Не проверено:** вживую (только на ПК пользователя).

### Обновления из настроек и автоматически; Telegram автора
- **Откуда.** Код и релизы в `ddddq` приватные, без токена приложение их не видит, а вшивать токен в программу нельзя. Поэтому сборка по тегу дополнительно публикует установщик и его SHA-256 в отдельный **публичный** репозиторий только с установщиками (`RELEASES_REPO`, по умолчанию `kuzak018-arch/dota-drafter-releases`). Описание версии берётся из `release-notes/vX.Y.Z.md`. Для публикации нужен секрет `RELEASES_TOKEN` (fine-grained токен с правом Contents: read and write только на этот репозиторий). Без секрета сборка не падает, а пишет предупреждение.
- **Бэкенд** (`backend/drafter/updates.py`, `GET /update/check`, `POST /update/download`, `GET /update/ready`): последняя версия из GitHub API, сравнение версий, загрузка задачей с процентами в `data/updates`. Файл остаётся только при совпадении SHA-256, без контрольной суммы не скачивается, старые загрузки удаляются.
- **Установка** (`app/src-tauri/src/update.rs`). Запускается только наш установщик из папки обновлений (путь проверяется), в пассивном режиме поверх (`/P /UPDATE`): без мастера, ярлыки, настройки и данные сохраняются. «Установить и перезапустить» — сразу, с `/R` (новая версия запускается сама). В автоматическом режиме — при выходе из программы.
- **Интерфейс** (Настройки → «Версия и обновления», `app/src/lib/updates.ts`): версия, «Доступна версия X · N МБ», описание, «Скачать обновление» (с процентами), «Установить и перезапустить», проверка вручную. Переключатель «Обновлять автоматически» включён по умолчанию: проверка через 20 с после запуска и каждые 6 часов, загрузка в фоне, установка при закрытии. На кнопке настроек — точка, когда есть новая версия.
- **Telegram автора:** в той же карточке — `@kuzak0` с белой минималистичной иконкой самолётика, открывается в браузере (t.me добавлен в разрешённые ссылки).
- **Решено самостоятельно:** не плагин updater Tauri: он требует подпись и ключ в секретах, а здесь целостность даёт SHA-256 из выпуска по HTTPS (как и было решено: подпись не нужна). Номер версии берётся из тега (следующий — v1.2.0).
- **Проверено:** 6 тестов (сравнение версий, «новее / та же / старше», нет выпусков, загрузка со сверкой и удалением старой, подменённый файл удаляется, без контрольной суммы — отказ), `cargo check` под Windows, `tsc`, карточка в браузере в обеих темах. **Не проверено:** настоящая установка (только на ПК, после первого выпуска в `RELEASES_REPO`).

### Оформление → «Свои VPK»
- Новая вкладка: кнопка «Добавить .vpk», и готовый мод Доты одним файлом ставится в папку языка озвучки (`game/dota_<язык>/`, туда же, где фон меню) под первым свободным номером `pakNN_dir.vpk` начиная с 03 (02 — наш фон). Чужие файлы не перезаписываются. Список поставленных: имя файла, под каким номером, сколько файлов внутри, размер, верхние папки, «файл изменён или удалён». Каждый можно убрать отдельно, «Убрать всё» убирает и их.
- Проверки (`install.py: check_pack/install_pack`, `vpk.py: vpk_entries`): это VPK v1/v2, файл не обрезан, все данные внутри `_dir.vpk` (многотомный мод с `_000.vpk` не принимается: Дота не нашла бы данные), тот же файл дважды не ставится, до 1,5 ГБ. Предупреждение, если мод меняет те же файлы, что фон меню или другой мод в папке (в игре сработает один). Как и всё «Оформление игры»: только когда переключатель включён после предупреждения, при закрытой Доте и не английской озвучке. Удаляется только наш файл с тем же SHA-256: если файл подменили, его не трогаем.
- Правило безопасности в CLAUDE.md дополнено этим исключением.
- **Проверено:** 4 новых теста (номера после фона, предупреждение о пересечении, повтор, запущенная Дота, битый, многотомный и обрезанный файл, подменённый файл не удаляется, API без согласия → 422), весь набор 243; в браузере на подставной Доте: файл встал как `pak03_dir.vpk`.

### Оверлей: исправление скругления (вместо области окна)
- **Что сломалось.** Обрезка окна по форме (`SetWindowRgn`) в Windows переключает окно на классическую рамку: у пользователя сверху появился заголовок как в Windows XP («Dota Drafter — оверлей» с кнопками), а углы Acrylic так и остались квадратными. Обрезка убрана полностью.
- **Как теперь.** Скругляет сама Windows 11. В режиме Acrylic у окна оверлея включается тень (`set_shadow(true)`): окно без рамки с тенью сохраняет системную рамку (tao убирает её только в `WM_NCCALCSIZE`), а такие окна Windows 11 скругляет на 8 px. Дополнительно явно задаётся `DWMWA_WINDOW_CORNER_PREFERENCE = DWMWCP_ROUND`. Панель в этом режиме тоже скруглена на 8 px, чтобы края размытия не выглядывали. В режиме «затемнение» (без системного размытия) тени нет, углы окна прозрачны и не видны, у панели прежние 26 px. В Windows 10 углы останутся прямыми (там нет такого скругления).
- **Проверено:** `cargo check` под Windows. **Не проверено:** вживую — после сборки на ПК пользователя.
