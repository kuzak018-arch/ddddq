# Dota Drafter: план

Статус: план одобрен 16.10.2026. **Этапы 0–6 готовы** (у этапа 6 точность на настоящих скриншотах ещё не измерена), следующий — этап 7 (установщик).
Патч на момент плана: 7.41f.

Решения по вопросам: аккаунт `1477734386` (Ancient 1, данные матчей открыты). Ранг берём из профиля OpenDota. Только рейтинговый All Pick. Только Windows 11. Rust установлен. Старый конфиг GSI на этапе 5 удаляем и ставим свой. Скриншоты драфта пользователь пришлёт перед этапом 6: **напомнить**. Коммит после каждого этапа. Факты и замеры, на которых основан план, лежат в [RESEARCH.md](RESEARCH.md).

## Коротко о главном

- **Матчи берём из OpenDota Explorer.** За сутки там около 476 тыс. ранговых матчей с героями, один запрос отдаёт 50 тыс. за секунду. Сбор данных займёт минуты, а не дни.
- **Позиции, билды и порядок прокачки — только из Stratz.** У OpenDota этих данных по пабам нет: разобранных ранговых матчей за неделю ноль. Нужен бесплатный токен Stratz (вопрос 3).
- **Почему прошлое чтение экрана работало плохо, и что меняем.** Скорее всего, сравнивались картинки с сайта с картинкой всего монитора. Теперь захватываем **только окно Доты** через Windows Graphics Capture, поэтому оверлей не попадает в кадр. Зоны фиксируются калибровкой. Сравнение идёт с портретами, вырезанными из **твоей же игры**: приложение учится на твоих исправлениях. Если уверенности нет, слот остаётся пустым. Точность меряем на сохранённых скриншотах до того, как функцию включать.
- **Valve в 2024 закрыла данные об игроках на стадии драфта.** Мы такие данные и не используем: только общая статистика по героям (как у Dota Plus) и то, что видно на экране.

## Архитектура

```
┌──────────── Tauri 2 (Rust) ─────────────┐        ┌──────── Python backend (sidecar) ────────┐
│ main window: React + TS, Liquid Glass   │  HTTP  │ FastAPI на 127.0.0.1:<случайный порт>    │
│ overlay window: прозрачное, поверх всех,│◄──────►│  + токен в заголовке                     │
│   Acrylic, сквозные клики               │   WS   │ data/   сбор OpenDota, Stratz, Valve     │
│ global-shortcut, window-state,          │        │ model/  модель, подсказки, объяснения    │
│ single-instance, запуск sidecar         │        │ builds/ теги героев, правила, билды      │
└─────────────────────────────────────────┘        │ gsi/    приём GSI (свой порт)            │
                                                   │ vision/ захват окна, шаблоны OpenCV      │
        Dota 2 ── GSI POST ──────────────────────► │ storage: DuckDB + Parquet, кэш иконок    │
                                                   └──────────────────────────────────────────┘
```

Структура репозитория:

```
backend/   requirements.txt (версии зафиксированы), drafter/{data,model,builds,gsi,vision,api}, cli.py, tests/
app/       Tauri 2 + React + TS (Vite), src-tauri/
shared/    hero_names.json, item_names.json (из dota2-tierlist), hero_tags.yaml, build_rules.yaml
data/      (в .gitignore) parquet матчей, кэш Stratz, модели, иконки, шаблоны портретов
reports/   отчёты модели и точности чтения экрана
```

Почему Tauri, а не Electron: прозрачное окно поверх всех, Acrylic, сквозные клики, глобальные клавиши и сохранение позиции у Tauri 2 есть из коробки или плагинами. Сам Tauri весит около 10 МБ, Electron около 150 МБ. WebView2 построен на Chromium, поэтому преломление через SVG-фильтр из твоего тир-листа заработает. Electron понадобится, только если на этапе 4 сквозные клики или Acrylic поведут себя плохо поверх Доты. Тогда скажу и предложу замену.

## Этапы

Каждый этап заканчивается коротким отчётом «что сделано и как проверить», а этот файл обновляется.

### Этап 0. Подготовка
- Установить Rust (`winget install Rustlang.Rustup`, нужно твоё согласие, вопрос 4).
- Создать каркас репозитория, `git init`, venv, `requirements.txt` с фиксированными версиями. Скопировать наработки из dota2-tierlist (оригинал не трогаю).
- **Проверка:** `python -m drafter.cli doctor` выводит версии, доступность OpenDota и Stratz, путь к Доте и её режим окна.

### Этап 1. Данные и модель
1. **Константы**: герои, предметы, способности, таланты, только активные facets, иконки, русские имена. Новый герой без русского имени даёт предупреждение.
2. **Сбор матчей**: Explorer, ranked All Pick, начиная с 7.41f, страницами по 50 тыс. Сбор можно продолжить после обрыва, вежливый темп (1 запрос в 2 с, укладываемся в лимиты). Фильтры: все 10 героев известны, длительность не меньше 15 минут (отсекаем ливы и ранние сдачи), без дублей. Запускается в фоне, я за ним не слежу.
3. **Stratz** (если будет токен): проверяю схему интроспекцией, потом выкачиваю по каждому герою позиции, предметы по фазам, прокачку, таланты, матчапы по брекетам. Кэш на патч.
4. **Позиции**: Stratz плюс EM-оценка по нашим матчам, сравниваю их между собой. Для подсказок герой считается играбельным на позиции, если `P(позиция | герой) ≥ 10%` на твоём брекете.
5. **Модель вероятности победы** (подробности ниже). Отчёт `reports/model.md`: сравнение с бейзлайном по стадиям драфта и брекетам, калибровочная кривая.
6. **Подбор героя под роль, подсказки по банам, объяснения.**
7. **Личные данные**: твоя история, пул героев и комфорт (винрейт сглаживается, чтобы 3 игры из 3 не выглядели как 100%), позиции в твоих матчах.
- **Проверка:** `cli collect`, `cli train`, `cli report`, `cli suggest --allies ... --enemies ... --pos 3` в консоли. Отчёт модели с цифрами.

### Этап 2. API бэкенда (FastAPI)
- `GET /heroes`, `GET /meta/tierlist?pos&bracket&days`, `GET /heroes/{id}` (матчапы, синергии, билды, моя статистика).
- `POST /draft/evaluate`: вероятность победы, доверительный интервал, вклад пар героев.
- `POST /draft/suggest`: топ-10 под мою позицию с причинами. `POST /draft/bans`.
- `GET /builds/{hero}?pos&bracket`, `POST /builds/{hero}/vs`: билд против драфта с причинами.
- `GET /me/*`, `POST /data/refresh` (задача «обновить после патча» с прогрессом), `GET /jobs/{id}`.
- `POST /gsi`, `WS /events` (стадия игры, мой герой, распознанный драфт → в интерфейс), `/vision/*`, `/settings`.
- Доступ только с 127.0.0.1 и только с токеном, который генерирует оболочка при запуске.
- **Проверка:** `pytest` (контракты, крайние случаи вроде пустого драфта или одного героя в двух слотах) плюс `/docs` (Swagger) в браузере.

### Этап 3. Основное окно и дизайн
- Страницы: **Драфт**, **Мета** (тир-лист), **Герой**, **Билды**, **Профиль**, **Настройки**.
- Драфт: 5+5 слотов и баны, выбор позиции 1–5, поиск по сленгу и с исправлением раскладки, горячие клавиши (`/` открывает поиск, `1–5` и `Shift+1–5` выбирают слот, `Del` очищает, `B` переключает на баны). Шкала вероятности победы с разбором пар. Топ-10 с причинами. Переключатель «учитывать мои комфортные пики».
- **Liquid Glass**: стеклянные панели (`backdrop-filter` с размытием и насыщенностью), преломление по краям через SVG-карту смещения из тир-листа, блики, мягкие тени, пружинные анимации (motion). Текст на стекле читается на любом фоне: подложка с затемнением под текстом и проверка контраста.
- **Фон**: встроенные градиенты и изображения, свой файл, ползунки размытия и затемнения.
- Тёмная и светлая тема, по умолчанию как в системе.
- Стек: React 19, TypeScript, Vite, Zustand, TanStack Query, motion.
- **Проверка:** запускаю окно, сам прохожу сценарий драфта, присылаю скриншоты обеих тем.

### Этап 4. Оверлей
- Второе окно: прозрачное, поверх всех, без рамки и без значка в панели задач. Acrylic размывает игру под окном. Если Acrylic недоступен, окно становится затемнённым полупрозрачным стеклом.
- Перетаскивание, изменение размера, ползунок прозрачности, запоминание позиции (window-state).
- Режим сквозных кликов. Глобальная клавиша показать или скрыть и вторая для включения взаимодействия. Обе настраиваются. Проверка конфликтов по твоим биндам Доты (их файлы только читаются).
- Если Дота в эксклюзивном полноэкранном режиме (`video.txt`, стиль окна), показывается подсказка, как переключить. Сейчас у тебя уже «окно без рамки».
- **Режим производительности**: во время игры отключаются размытие, преломление и анимации, обновления реже.
- Компактные режимы: «драфт» (вероятность победы, топ-5 под роль, баны) и «билд» (предметы против драфта).
- **Проверка:** оверлей поверх запущенной Доты, клики проходят сквозь, клавиши работают. Замер FPS в игре с оверлеем и без него.

### Этап 5. Game State Integration
- Установить свой конфиг GSI (с твоего согласия, вопрос 6) на отдельный порт с токеном.
- Сначала логгер: пишет всё, что приходит, на одном реальном матче или лобби с ботами. Так узнаем, приходит ли игроку блок `draft`.
- Логика: стадия выбора героев → показать оверлей в режиме драфта. Пик → подставить моего героя и сторону. Начало игры → режим билда против вражеского драфта плюс режим производительности. Конец матча → свернуть.
- **Проверка:** воспроизведение записанного лога GSI без игры (тест) и один живой матч.

### Этап 6. Чтение драфта с экрана (экспериментально, отключаемо)
- Захват только окна Доты (`windows-capture`, WGC), 1–2 кадра в секунду и только на стадии драфта по GSI. Бэкенд DPI-aware, у тебя масштаб 125%.
- **Мастер калибровки**: снимок экрана драфта → ты отмечаешь рамки слотов (готовые пресеты для 16:9 масштабируются под разрешение) → предпросмотр распознавания.
- **Распознавание**: нормализованная кросс-корреляция (OpenCV) по серому изображению и по цвету в каждой зоне, отдельно для пиков и для банов (у банов серые или перечёркнутые портреты).
- Шаблоны: портреты со Steam CDN плюс **вырезки из твоей игры**. Каждая твоя ручная правка сохраняет вырезку как эталон этого героя, и со временем точность растёт.
- Решение: порог уверенности плюс отрыв от второго кандидата плюс совпадение в 2 кадрах подряд. Иначе слот остаётся пустым. Ручная правка всегда важнее, распознавание её не перезаписывает.
- Стенд точности: папка с размеченными скриншотами → precision и recall по слотам → `reports/vision.md`. Включаем функцию, только если precision ≥ 98%.
- **Проверка:** отчёт точности на твоих скриншотах (вопрос 7) плюс живой драфт.

### Этап 7. Установщик
- Бэкенд собирается PyInstaller в один exe-sidecar, Tauri собирает установщик NSIS.
- Мастер первого запуска: аккаунт, токен Stratz, путь к Доте, GSI, оверлей.
- Кнопка «Обновить данные после патча»: константы → матчи с начала нового патча → Stratz → пересчёт модели → отчёт. Если матчей с начала патча ещё мало, предупреждает об этом.
- **Проверка:** установка на чистого пользователя Windows, запуск без dev-окружения.

## Модель

- **Данные**: ranked All Pick текущего патча, по умолчанию с 7.41f (порядка 3–5 млн матчей после фильтров, около 200 МБ Parquet). Брекет считается по `avg_rank_tier`.
- **Разбиение по времени**: обучение на старых днях, валидация на следующих, тест на последних 2 днях. Ничего из будущего не попадает в прошлое.
- **Бейзлайн**: `logit P(radiant) = c + Σ logit(wr героя Radiant) − Σ logit(wr героя Dire)` на твоём брекете.
- **Логистическая регрессия**: признак +1/−1 для каждого героя плюс суммы синергий союзных пар и контрпиков вражеских пар.
- **Синергии и контрпики** считаются **только на обучающей выборке**, со сглаживанием (empirical Bayes, у редких пар оценка тянется к нулю). Для строк самого обучения используется out-of-fold, иначе модель увидит ответ.
- **Бустинг** (LightGBM) на тех же агрегатах плюс брекет и признаки состава: покрытие позиций, доля магического урона и контроля.
- **Неполный драфт**: при обучении случайно скрываю часть героев, чтобы модель работала на 1v1, 3v3 и 4v5. Качество меряю отдельно для каждой стадии.
- **Калибровка**: Platt или isotonic на валидации. Метрики: log loss, Brier, ROC AUC, точность, ECE. Калибровочная кривая выводится в отчёт.
- **Честные ожидания**: по одному драфту в пабах исход предсказывается слабо. Типичный уровень — AUC около 0,58–0,62 и точность 55–58% на полном драфте. Прирост над бейзлайном измеряется в долях процента. Это будет в отчёте как есть, без подгонки. Ценность подсказок в относительном сравнении героев, а не в абсолютной цифре.
- **Подбор героя**: для каждого доступного героя на моей позиции считается `ΔP = P(победа | драфт + герой) − P(победа | драфт)`. Разбор: сила в мете на позиции и брекете, кого контрит (со вкладом каждого врага), с кем синергия, мой комфорт (если включено), **уязвимость к контрпику** (насколько популярные оставшиеся герои его контрят). Последнее важно при раннем пике.
- **Баны**: угроза героя = сила в мете на брекете плюс насколько он контрит уже взятых союзников (или мой пул, если союзников ещё нет) плюс герои, против которых я сам чаще проигрываю.

## Билд против драфта
- `hero_tags.yaml`: черновик собирается автоматически из данных способностей (тип урона, иллюзии, невидимость, лечение, призыв существ, сайленсы, пробивание BKB, развеиваемость), потом я вычищаю его вручную. Теги, например: `magic_burst`, `illusions`, `invis`, `heal`, `evasion`, `summons`, `physical_burst`, `lockdown`, `silence`, `armor_reduction`, `mana_burn`, `strong_passives`, `dispellable_buffs`.
- `build_rules.yaml`: условие по вражеским тегам → предметы → объяснение по-русски. Например: 3+ героя с магическим бурстом → BKB, Pipe, Eternal Shroud. Иллюзии → Mjollnir, Battle Fury, Shiva's. Невидимки → Dust, Sentry, Gem. Сильный хил → Spirit Vessel, Shiva's. Пассивки → Silver Edge. Уклонение → MKB, Bloodthorn.
- Рекомендации отбираются по моей позиции и по тому, что реально собирают на этом герое (данные Stratz), и сортируются по угрозе: вражеский кор важнее саппорта.
- Если Stratz отдаёт винрейт предмета по таймингу, он используется поверх правил. Винрейта предметов против конкретных героев в открытых данных не нашёл. Если найду, добавлю.

## Риски и ограничения
- **GSI**: блок `draft`, скорее всего, приходит только зрителю. Тогда драфт вводится вручную или читается с экрана. Проверим на этапе 5.
- **Stratz**: без токена позиции и билды будут слабее (EM-оценка позиций и про-билды OpenDota). Лимиты Stratz нужно проверить.
- **Immortal**: открытых данных нет, используем Divine.
- **Чтение экрана**: серая зона правил Valve, хоть память игры и не читается. Поэтому функция отключаемая, и захват идёт только на стадии драфта.
- **FPS**: Acrylic и анимации стоят GPU, поэтому есть режим производительности и замер на этапе 4.
- **Explorer OpenDota** — общий ресурс. Сбор идёт вежливо, а если explorer закроют, перейдём на `/publicMatches` (медленнее).

### Исправление билдов (17.10.2026)
- Главная причина: без `matchLimit` Stratz отбрасывал строки покупок по минутам с малым числом матчей. У саппортов и на редких позициях пропадали Blink, Glimmer, Aghanim's (у 56 сборок из 286 коровые были пустыми). Теперь запрос идёт с `matchLimit: 10`.

- Страница «Билды» на позиции, где героя почти не играют, показывает билд основной позиции с пометкой.
- Итог проверки по всем 286 сборкам: пустых коровых 0 (у Chen 4 один предмет, там 283 матча за неделю), долей выше 100% нет. Таланты с «?» остались у Tinker и Naga: этих чисел нет в данных Valve.
