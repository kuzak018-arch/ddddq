# Dota Drafter

Помощник драфта Dota 2 для Windows 11: Tauri 2 + React/TypeScript (`app/`) и Python FastAPI (`backend/`).
Журнал этапов и все решения — в `PLAN.md`, устройство — в `README.md`.

## Как работаем
- Отвечать пользователю по-русски, коротко и по делу.
- Без заглушек: каждую часть проверять (тесты, проверка типов, по возможности живой запуск).
- После каждого законченного куска — запись в `PLAN.md` (что сделано, что проверено, что решено самостоятельно) и коммит.
- Никогда не коммитить `.env`, `secrets/` и `data/`.
- Правило безопасности игры: никакого чтения памяти Доты, инъекций и правки её файлов. Можно только конфиг GSI, захват картинки окна и открытые API (OpenDota, Stratz). Единственное исключение — файл сеток героев пользователя `hero_grid_config.json` (Steam → userdata → 570 → remote → cfg): только по кнопке, только при закрытой Доте, с резервной копией и слиянием, которое трогает лишь сетки с префиксом «Драфтер · » (`backend/drafter/hero_grid.py`, там же проверка и откат).

## Команды
```bash
# тесты бэкенда (из backend/)
python -m pytest -q tests
# проверка типов интерфейса (из app/)
npx tsc --noEmit -p .
# API для разработки и интерфейс в браузере
python -m drafter.api --port 47900     # из backend/
npm run dev                            # из app/, http://localhost:1420
```

## Что есть только на ПК пользователя
- `data/` (~300 МБ): база матчей OpenDota, обученная модель, константы, иконки, кэши Stratz. В облаке и на GitHub её нет, поэтому тесты, которым нужны данные, пропускаются (`skipif`): на чистой машине 22 проходят, остальные пропущены. Это нормально.
- `.env` с `STRATZ_TOKEN` и `DOTA_ACCOUNT_ID`. Без токена всё, что ходит в Stratz, отвечает «нет токена».
- Проверка вживую с Дотой (GSI, захват окна, оверлей) возможна только на ПК пользователя.
- Сборка установщика в облачной сессии невозможна (Linux). Его собирает GitHub Actions на Windows.

## Выпуск версии
1. Изменения в ветке → PR в `main` (проверка `check.yml`: тесты и `tsc`).
2. После слияния — тег `vX.Y.Z` (больше предыдущего): `git tag v0.3.0 && git push origin v0.3.0`.
3. `release.yml` собирает подписанный установщик и публикует его с `latest.json` в публичный репозиторий релизов (переменная `RELEASES_REPO`). Установленные копии обновятся сами: «Настройки → Обновления».
- Если менялись модель или данные Stratz, сначала на ПК пользователя: `scripts/publish-seed.ps1`. Без этого сборка возьмёт старые стартовые данные.
- Ключ подписи обновлений: `secrets/updater.key` (только на ПК) и секрет `TAURI_SIGNING_PRIVATE_KEY` на GitHub. Без него установленные копии новую версию не примут.
